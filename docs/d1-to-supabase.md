# نقل ASQARYA-MOSSA من D1 إلى Supabase — مرحلة النسخة الاحتياطية

**الحالة: تجهيز نسخ وتدقيق، وليس نقل الإنتاج.** قاعدة Cloudflare D1 ما تزال المصدر التشغيلي إلى أن تنجح المطابقة ويتحوّل كل مسار API. لا تُحذف D1 ولا تُغيّر سجلات الفواتير أو الترحيلات خلال هذه المرحلة.

## 1. استخراج قاعدة D1 الأصلية

من Cloudflare افتح Worker `asqarya-mossa` ← Settings ← Bindings، وحدد اسم قاعدة D1 المرتبطة بالاسم `DB`، ثم شغّل Wrangler على جهاز موثوق مسجّل الدخول إلى حسابك:

```bash
npx wrangler d1 export <D1_DATABASE_NAME> --remote --output=./asqarya-d1-private.sql
```

استبدل `<D1_DATABASE_NAME>` بالاسم الحقيقي الظاهر في لوحة Cloudflare. تصدير D1 قد يتعذر مؤقتًا إذا فشلت الخدمة أو تجاوزت حدود الاستخدام. **احتفظ بملف SQL محليًا، ولا ترفعه إلى GitHub أو مساحة عامة.** هذا الملف قد يحتوي سجلات عمل وبيانات جلسات حساسة.

## 2. بناء جرد قابل للمقارنة

```bash
python scripts/prepare-d1-backup.py ./asqarya-d1-private.sql --output-dir ./private-d1-audit
python scripts/test-prepare-d1-backup.py
```

ستنتج `manifest.json` وفيه عدد الصفوف وبصمة SHA-256 لكل جدول، و`rows.jsonl` يحفظ كل صف مع مفتاحه وبصمته. **كلا الملفين خاصّان؛ لا يُرفعان إلى GitHub.**

## 3. حالة Supabase

في مشروع Supabase `kgzmusavcsbsxqftdjcg` أنشئ مخطط خاص `institution_migration` وجدولان: `d1_exports` و`d1_export_rows`. الجداول معزولة عن Data API وصلاحيات `anon` و`authenticated`، وبقيت فارغة عند تجهيز هذه المرحلة. لا يوجد نقل آلي من SQL إلى PostgreSQL في هذه الدفعة.

## 4. بوابات الأمان قبل النقل الفعلي

- لا يبدأ الاستيراد إلا بعد حفظ نسخة D1 خام مستقلة وبصمتها.
- نطابق أعداد الفواتير والمجموعات وترحيلات SAP والقرارات والاستثناءات ومجموعة الترحيلات، وبصمات السجلات في المصدر والهدف.
- ندقق مستودع 011، والإلغاء والعكسيّات، وربط الترحيلات والفواتير، وتواريخ الورق المستقلة.
- تحويل كل API إلى PostgreSQL يتطلب إعادة كتابة استعلامات SQLite/D1 (مثل `json_each` و`json_extract` و`batch`) واختبارات معاملات وسلامة بيانات.
- لا نفصل D1 قبل تشغيل متوازٍ للقراءة واختبارات كتابة وخطة رجوع ونسخة احتياطية حديثة.
- لا تُرفع أسرار الاتصال إلى الواجهة أو GitHub.
